# 基本的なルール

- プロダクトコードを作成・変更した場合は、次のような確認を行い問題が発生していないことを確認する。テストコード、ドキュメントは除く
  - ファイルの修正後に、`pnpm prettier --write <ファイルパス>` と `pnpm eslint --fix <ファイルパス>` を実行しフォーマットを行う
  - プロジェクトルートで `pnpm test:run <パターン>` を実行し、対象ファイルのテストを実行する（例: `pnpm test:run mermaid`）。テストケースを修正すべきか判断に迷った場合は確認する
  - 対象パッケージのディレクトリで `pnpm tsc --noEmit` を実行し、TypeScript のチェックを行う
- テストコードの作成・変更をする場合はスキルを使用する
- .ts、.tsx のファイルには適切な TSDoc を記述する
- TSDoc の記述は **英語** を使用する

## コーディングスタイル

- 可能な限り `let` より `const` を使用し、関数型スタイルを優先する
- 小さな単一責任の関数に分割する

## React コンポーネント

- 新規コンポーネント作成・変更時は `vercel-react-best-practices` スキルで検証する
- JSX を使用するファイルでは `import React from 'react'` を明示的に記述する

## コミットに関するルール

このルールはスキルより優先させる

- コミットをする場合はスキルを使用する
- コミットメッセージは **英語** を使用する
